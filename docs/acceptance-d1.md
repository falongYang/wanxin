# 晚信 D1 验收用例（测试 + 部署侧）

规格来源：`docs/design.md`、`docs/superpowers/plans/2026-11-25-mvp.md`（第一天）。
范围：角色发现 + 可持续聊天。本文件只定义用例，不含实现；待 Codex 交付可跑版本后逐条执行。
原则：先在本地/测试替身跑通；真实模型回复、上线部署另按闸门执行。

## 闸门（缺一不动线上）

1. 项目经理双视口 + 哈希核验通过；
2. owner 真机验收通过；
3. owner 在群里点名具体版本。
以上三条齐备才发版/推远端。本轮只写用例、备部署链，**不部署**。

## 用例

### TC-D1-01 成年确认入口
- 前置：全新访客，无 Cookie。
- 步骤：首次打开角色发现页 → 查看是否先展示成年确认与 AI 说明。
- 预期：未确认前不进入聊天；确认后 `adultConfirmedAt` 写入，初始化线程与固定开场；已有会话的访客直接进入原线程。

### TC-D1-02 三条开聊建议可编辑
- 前置：已成年确认，进入聊天页，首次发送前。
- 步骤：分别点击「聊聊今天」「给今晚点首歌」「接一段电台故事」。
- 预期：三条只填入输入框、不自动发送；内容可编辑后再发；输入框始终允许自由输入。

### TC-D1-03 首次发送收到真实回复
- 前置：成年确认，进入聊天。
- 步骤：输入一条具体消息并发送。
- 预期：收到林舟的回复，口吻简短具体、顺着已说细节；头像旁持续标注「AI 虚构角色」。
- 备注：模型 key 未到位前，用测试替身跑通链路；「真实回复」一项待 key 到位后单独复验，不得用替身结果冒充。

### TC-D1-04 刷新恢复
- 前置：已有多条往来消息。
- 步骤：刷新页面。
- 预期：同一访客身份下消息历史完整恢复，顺序、内容与刷新前一致。

### TC-D1-05 失败重试去重（断网重试只出一条用户消息）
- 前置：可注入网络故障/服务异常。
- 步骤：发送消息 → .mock 失败 → 原位重试同一请求（相同 `requestId`）多次。
- 预期：失败时保留已提交消息、状态为可重试；重试只产生一条用户消息，回复不重复；相同 `requestId` 复用同一条用户消息。

### TC-D1-06 跨访客隔离
- 前置：访客 A、访客 B 各持独立 Cookie。
- 步骤：A 持自己的线程/消息标识，尝试用 B 的身份读取。
- 预期：跨访客资源标识返回 404；所有读写按当前访客查询，无数据串台。

### TC-D1-07 输入边界
- 步骤：①发送空白/纯空格；②发送 1001 字。
- 预期：空白忽略不发送；超 1000 字按设计拒绝或截断（以 design.md「最多 1,000 字」为准）。

### TC-D1-08 等待中限制重复发送
- 步骤：消息等待回复期间连续点发送。
- 预期：等待期间限制重复发送，不产生多条并行请求。

## 待部署链就绪项（不阻塞本轮用例编写）

- 部署脚本：待上述入口/卷/目录明确后落地，避免写成无法核验的空脚本。
