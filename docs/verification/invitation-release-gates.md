## 威胁检查与阻断结论

当前阻断项：未确认 HTTPS/同源入口及持久卷；缺少目标备份恢复与权限证据；无邀请准入、访客限流和全局每日预算；真实模型配置/质量未验；日志隐私运维与最小错误观测未闭环；发布构建不可从锁文件复现；部署/回滚未演练；三闸门未齐。

| 威胁 | 当前控制与剩余风险 | 放行前检查 |
| --- | --- | --- |
| 刷新身份/批量请求耗费模型费用、磁盘 | 成年自报可批量建身份；单线程互斥不阻止顺序调用 | 建会话/API分层限流、全局预算硬停止、磁盘/容量告警、受邀入口；只用合成负载验证 |
| Cookie被窃取、跨访客资源越权 | HttpOnly/Secure及所有权检查降低风险；Cookie本身就是访问凭证 | HTTPS、代理脱敏；独立身份完整读写回归，设备共享/清Cookie会失去身份的说明 |
| 跨站写入与跨源入口 | SameSite=Lax已有；未见Origin/Content-Type强校验 | 同源代理策略、跨站/同站其他子域请求测试，明确可信Origin；若控制不足补服务器校验后复验 |
| 资源耗尽/慢请求/数据库竞争 | 请求体字符上限和模型超时已有；无全局并发/连接/存储限额 | 代理体积与超时限制、全局并发阈值、磁盘监控；单实例先验证；不把字符上限等同字节上限 |
| 提示注入/不当生成 | 卡片以用户上下文传入，系统提示声明虚构；不保证模型遵循 | 用合成恶意卡片检查越权引导、密钥索取、未成年人及危险话题应答；确认模型服务政策与退出/反馈处理责任人 |
| 备份或日志泄露、删除后复活 | SQLite含聊天正文；删除API清当前库，不清历史备份 | 权限最小化、备份加密/保留期限、恢复后删除重放或等效流程；向试用者说明保留与删除边界 |
| 错版/不兼容回滚 | 共享工作区有未提交改动，HEAD无法代表页面 | 固定最终源代码、制品及迁移版本；哈希绑定三闸门；有任何改动重新核验对应候选 |

## 持久化备份与恢复操作清单（待环境确认）

当前可演练方案采用**维护窗口停写备份**，会有停机。未验证在线热拷贝，不允许对运行中的SQLite直接cp；未来启用WAL后尤其不能漏掉事务状态。

1. 确认绝对数据库路径和持久卷挂载，服务账号最小读写权限；记录当前版本、配置引用和数据库结构版本，备份目录限制权限，不放Web根目录。
2. 停止新请求并排空在途模型调用，然后停止所有数据库写入进程；确认没有其他实例写库。现有服务未实现专用优雅排空，需环境层维护与等待步骤，不能把kill直接当成功排空。
3. 在所有连接关闭后复制数据库到受限备份位置，记录时间、版本、校验和；在副本执行 `PRAGMA integrity_check`，结果必须为 `ok`。按批准策略加密并复制到独立故障域；复制失败或校验失败即备份失败。
4. 恢复演练写到全新隔离目录，校验和与完整性通过后启动同版本服务，使用合成身份验证消息/卡片/成年时间、跨访客隔离、清除会话。不覆盖原库；记录备份时间、恢复耗时、结果及责任人，比较RPO/RTO。
5. 事故恢复先备份事故库，暂停入口；经授权选择备份，执行删除数据处理策略后切换恢复库路径。确认恢复会话与模型预算状态；预算尚未持久化前不得放行。成功后才恢复入口，原库保留受控回退副本。

## 部署与回滚步骤（只准备，当前不执行）

环境未知，因此不编造可直接运行的远程脚本。owner输入与安全阻断项闭环后，按确定的进程/代理/卷生成可审阅的版本化配置；不能用本清单作为部署授权。

1. 固定候选提交、依赖锁、Node版本、构建命令和制品；在干净环境完成测试/构建，记录源代码与制品SHA-256，保存上一版制品与环境配置引用（无密钥值）。
2. 在隔离环境配置同源静态站点与API代理、持久卷、最小权限运行账号、密钥注入、限流与预算、脱敏日志与监控；用替身完成流程、重启及备份恢复。真实模型仅另行授权后验证。
3. 项目经理验证最终候选双视口与哈希；owner用真机走成年确认、聊天、两卡收藏、刷新、编辑续聊、删除/清除、软键盘及失败重试；owner在群里点名同一具体版本。三项齐备并记录后才能继续发版/推远端，不能用本工单完成代替授权。
4. 后续获授权的发布窗口：宣布维护、排空、停写备份，核验挂载与旧版回退制品；切换到已批准制品/配置，启动并确认生产模式、同源HTTPS、内部端口、预算开关。
5. 用独立合成访客做冒烟：成年入口、真实回复、刷新、两卡与隔离；检查错误/延迟、429/503、费用增量、磁盘和证书。不得将真实用户消息写进验收记录。异常时保持入口关闭并回滚。
6. 回滚触发：数据不可恢复/串台、密钥或正文泄露、预算失控、持续503/超时、入口或Cookie异常。暂停入口/模型调用并保留脱敏证据，切回前版制品和配置引用；优先保留当前数据，先验证结构兼容。若必须恢复备份，先批准可能丢失的数据范围并遵循上述恢复步骤；不盲目用旧程序打开不兼容库。
7. 回滚后再次做隔离、恢复和费用停止核验，记录版本/哈希、事故与恢复时点；继续观察错误率、调用量/费用、磁盘、证书续期、备份任务与恢复可用性。密钥泄露需另行吊销/轮换，仅代码回滚无效。

新增域名/主机/备份存储/模型调用可能产生成本，金额待owner方案和预算确定；本轮成本为本地计算，无购买。停写备份及单实例切换有停机，时长须演练后给出，不承诺零停机。撤销本次交付只需移除本文件与审计脚本，不涉及数据库或运行配置回滚。
