# 本地匿名试用指标

开发保留上限为7天，字段仅 `analysisId`、`event`、`occurredAt`。`analysisId` 是独立随机标识，通过本地映射关联当前访客以支持清除；它并不意味着数据不受隐私管理。事件不包含Cookie、业务消息/卡片标识、正文、标题、年龄、关系、IP或UA，不发送到外部服务，也没有公开分析API。

## 运行

需要Node >=22.13（支持node:sqlite）。在项目根目录：

```sh
node scripts/trial-metrics.mjs data/wanxin.sqlite
node scripts/trial-metrics.mjs data/wanxin.sqlite 2026-11-10T16:00:00.000Z
node --test tests/analytics.test.mjs
```

前两个命令以只读方式打开指定的已有数据库，输出聚合JSON，不输出身份或事件明细。路径以实际SQLITE_PATH为准，不要把数据库放入Web根目录或提交到仓库。第三个命令在临时合成数据库复验边界、迁移、去重及删除，结束清理，不需真实模型或访问已有数据库。

`asOf` 默认为当前时间，非法时间拒绝。窗口为 **W=(asOf−7×24小时, asOf]**：左边界不含、右边界包含、未来事件排除。脚本与计算函数都应用该窗口。输出 `windowStartExclusive`、`asOf` 和 `retentionDays`，并使用下列口径。

## 分子分母

所有指标按窗口内的匿名访客去重，不是消息次数或单卡因果。

| 输出 | 分母 | 分子 |
| --- | --- | --- |
| senderSaveRate | W内至少有一次有效新消息send的访客 | 其中在其W内首次send之后（时间戳≥）有card_save的访客 |
| saverNextDayReturnRate | W内首次card_save的访客，且该收藏的上海自然日次日已经完整结束 | 其中在该次日有card_open的访客 |
| openToSendRate | W内至少有一次card_open的访客 | 其中在W内首次card_open之后（时间戳≥）有card_send的访客 |

三个比率均输出 `numerator`、`denominator`、`rate`；分母0时rate为null。`windowSavingVisitors` 单独输出W内至少一次card_save的访客数，不要求W内发生发送，因此不会隐藏老访客仅收藏的活动。次日回看也独立于发送队列。

上海自然日按UTC+08:00划分。收藏发生在上海11月8日，只有到11月10日00:00才进入成熟分母；回看需发生在11月9日。此处“首次”均指窗口内首次，不宣称全历史首次。窗口移动后队列也会改变，不能把多个窗口比率相加。毫秒时间戳相同时无法从三个字段判断事件先后，转换口径使用≥；不宣称同毫秒因果。

## 事件与去重

- `first_send`：业务历史中真实第一次有效新用户消息；不因为事件过期而补造，不作为当前窗口发送分母。
- `send`：每次通过输入/所有权校验并首次写入业务消息的新发送。沿用requestId去重；失败后的同请求重试、成功请求重放不新增send。模型最终失败也仍是用户已发送，因此记入发送队列。
- `card_preview`：有效来源的预览请求。
- `card_save`：首次新增收藏；相同来源返回原卡片时不重复记录。
- `card_open`：已鉴权卡片详情读取；包括用于载入最新续聊引用的详情读取，不等同用户一定认真阅读。
- `card_send`：新发送明确引用一张有效卡片；模型失败后的重试不重复记录。

## 边界与历史限制

- 11月1日首次发送，11月9日仅收藏旧消息：在11月9日的七天窗口，发送收藏率0/0、rate=null，windowSavingVisitors=1。不能从已删除事件推算全历史分母。
- 11月9日又发送新消息，之后收藏该新片段：窗口发送收藏率1/1。不重建11月1日first_send。
- 窗口中只有先收藏后发送，且无后续收藏：发送分母1、转化0。
- 升级前没有send事件，历史发送不会回填；上线初期发送分母只覆盖升级后采集的新消息。旧first_send不能替代所有历史发送。对比不同版本或历史窗口时必须注明采集版本。
- 旧五动作表在应用初始化时以事务迁移，保留原事件和外键级联、恢复索引，不补历史send。该迁移需按正常发布备份/维护流程执行；本次验证仅操作合成库，没有迁移用户数据库。
- card_open→card_send仅表示同一访客先后动作，不证明使用同一张卡；字段不足以区分引导收藏和自然收藏，不额外采集私密信息。

## 保留与清除

应用初始化、处理请求和记录事件时会删除当前服务器时间七天前及更早的事件；指标读取本身不写库。没有定时清理进程，无流量停机期间不会物理删除旧行，因此“7天”是开发剪除阈值和查询上限，并非已证明后台持续按时删除。正式邀请前的保留期限、停机清理、访问权限及备份删除策略仍由owner核定。

清除会话通过访客外键级联删除其映射与全部事件；删除单张卡片保留无法直接定位卡片的匿名动作。访客映射保留到会话清除。恢复旧备份可能恢复已清除数据，需上线闸门中的删除恢复策略；本指标功能未解决备份运维。

指定过去asOf只会过滤当前仍存的数据，不能复原已剪除或已清除的数据；请求未来asOf不会生成未来行为，也可能将现有事件移出窗口。正式试用的存储位置、期限、授权查看人须经owner确认。
