# 晚信三天 MVP 实施计划

**目标**　交付可邀请试用的移动 Web 版本，覆盖详细设计中的全部首版功能。

**前提**　一名全栈开发者连续投入三天，每天约八小时。启动前具备可调用的模型账号、可部署环境和可用的 HTTPS 入口。若模型或部署凭据未就绪，当天先用测试替身完成本地验收，真实调用和上线验收仍待对应条件具备。

**规格**　[详细设计](../../design.md)。实现使用 React、TypeScript、Node 和 SQLite。目录建议为 `src/ui`、`server`、`tests`，现有 `prototype` 作为交互参照。

## 第一天 · 角色发现与可持续聊天

- [ ] 上午 4 小时。初始化应用、原型视觉、成年确认、角色发现与聊天布局。建立访客、线程及消息表。可选用 30 分钟做 REA 状态核对。
- [ ] 下午 4 小时。接入模型适配器，完成历史恢复、消息提交、超时、重试和请求去重。为跨访客与重复请求添加集成用例。
- [ ] 验收。首次打开可确认年龄、进聊天并收到真实回复。刷新恢复。模拟网络故障后重试只出现一条用户消息。
- [ ] 提交 `feat: add character discovery and chat`。

## 第二天 · 共同经历与续聊

- [ ] 上午 4 小时。支持选消息、生成草稿、取消、手动保存降级、编辑标题和正文、按来源去重。
- [ ] 下午 4 小时。实现卡片列表、详情、删除、从卡续聊、清除会话。验证跨访客隔离和删除后的上下文。
- [ ] 验收。收藏两张卡，刷新后编辑、续聊、删除。重复保存只保留一张，删除后模型调用中没有该卡或其派生上下文。
- [ ] 提交 `feat: add shared experience cards`。

## 第三天 · 移动端验收与试用发布

- [ ] 上午 3 小时。检查小屏和软键盘、对话滚动、空态、错误提示。补匿名事件、限流和模型预算。
- [ ] 下午前 3 小时。部署 HTTPS 试用环境与持久卷，跑真实模型冒烟。验证重启恢复和会话清除，记录试用步骤与已知问题。
- [ ] 最后 2 小时。预留给前三天缺陷回归。完整走一遍发现、聊天、卡片 CRUD、续聊、数据清除。
- [ ] 验收。核心用例全部通过，部署地址可访问，敏感配置未提交，输出可交付版本和试用说明。
- [ ] 提交 `chore: verify and publish MVP`。GitHub 认证可用后推送并核对远端提交。
