# 晚信视觉与交互改版实施计划

> 执行成员：使用计划执行技能逐项实施。用户已授权项目经理直接确定方案并推进，复用现有全栈成员，不新增代理。

**目标：** 借鉴参考项目的私人陪伴氛围，将晚信现有发现、聊天、经历卡流程做成统一且可体验的移动端产品。

**架构：** 保留现有 React、TypeScript、Vite、Node 和 SQLite 架构。改版集中在前端展示与交互，不调整模型协议、访客隔离和卡片数据契约。

**规格：** 本文设计部分及 `docs/design.md`；冲突时保留后者的数据、安全和业务规则。

## 设计依据与方案

参考：https://annvale.github.io/Lifeboat-open/ 。已读取公开页面源码及样式；页面声明应用画面为静态快照，交互细节来自站点说明，尚无实际操作验证。

参考特征：低饱和配色、衬线标题、细线层次、圆角、纸张收藏、消息操作和返回来源。仅借鉴设计原则，不复制品牌、角色、插画或整站源码。

考虑过仅调整视觉（更快，但收藏与回看仍割裂）及扩展参考项目全部功能（范围过大）。采用视觉与核心交互一起优化。用户选择由项目经理直接推进。

### 视觉

- 默认夜色：背景 #101726，表面 #1B2638，正文 #F4EEE4，次要文字 #B5BDCC，强调 #D9BA85。纸张卡片背景 #F3EBDD、正文 #302A26。
- 标题用系统宋体衬线，正文用现有系统字体，不依赖外部字体下载。
- 发现页以「晚信 / 深夜电台 / 林舟」建立层级；用原创 CSS 电台或海面意象营造场景，明确主按钮。
- 聊天头部紧凑，角色与 AI 标识持续可见；消息区为主，避免把每条消息做成工具面板。
- 共同经历采用信笺卡片，显示标题、摘要和日期。小屏单列；桌面仍保持适宜阅读宽度。
- 按钮触控区域至少 44px；320px 起无横向滚动；兼容底部安全区。动效 160–240ms，尊重减少动态效果设置。

### 交互

- 消息操作提供可见按钮打开菜单，不依赖长按；菜单含「做成经历卡」，点击外部或退出可关闭。
- 经历卡预览和编辑保留原有可编辑字段、来源及取消行为。保存成功给轻提示。
- 详情提供「查看来源」「编辑」「从这里继续聊」；查看来源进入原会话、定位并短暂强调原消息。若消息不在返回历史中，明确提示，不能跳错。
- 续聊继续使用现有 `sourceCardId` 引用，发送前可移除，不能自动发送。
- 保留失败重试、去重、加载、空状态、删除确认、成年确认和清除会话规则。主题切换、碎语队列、自动记忆不纳入。

## 全局约束

- 包含项目经理在内，运行代理最多 4 个；本轮仅项目经理和现有全栈成员参与。
- 不调用或创建 QA 代理，不部署、不推远端、不替用户提交。
- 不覆盖其他成员或用户的未提交改动，不修改应用运行配置。
- 不引入无必要依赖，不修改服务端接口和数据模型。

## 重点检查

1. 超长中文、换行和长链接不得撑出消息与纸张。
2. 小屏输入区、软键盘和安全区不遮住操作。
3. 来源不存在时给出解释；刷新后仍能正确定位存在的来源。
4. 回复等待、请求失败及卡片失效状态仍可恢复。
5. 键盘可访问菜单、关闭弹层后焦点合理、减少动态效果设置生效。
