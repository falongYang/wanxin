# 晚信产品与技术设计

## 产品定位

晚信是以单身年轻女性为核心用户的原创角色陪伴产品。首版以中文、移动端 Web 和一个原创角色「林舟」验证核心体验。林舟是一位在海边值夜班的电台主播。用户可以自由改变话题，并把想留下的一段对话保存成经历卡。卡片兼具可回看的内容与续聊入口。

验证假设是用户愿意保存共同经历，并在新鲜期过后主动从某一张卡重新开始对话。首版支持一个角色、多张经历卡、真实文本回复、刷新后恢复、记忆纠正和删除。交付目标是可邀请体验的 MVP。原生上架、多角色市场、语音、付费、推送和跨设备同步放到后续版本。

## 核心用户与招募

首轮以 **22–29 岁、单身、使用中文的年轻女性**为主要招募对象，优先覆盖初入职场、工作数年或处于升学到就业转换期的人。年龄区间用于首轮研究取样，产品仍面向成年人。招募时关注过去两周是否有想找地方聊聊日常、记录感受或体验角色故事的时刻。单身身份仅作自愿提供的研究信息，产品注册无需采集。这个人群范围是立项假设，现有竞品调研无法证明她们已经占同类产品用户的大多数。

| 使用动机 | 触发时刻 | 期待的体验 | 产品回应 |
| --- | --- | --- | --- |
| 想讲讲今天 | 下班路上、回家后或睡前，脑子里还有一件事 | 无须解释太多，就能把话说下去 | 开场给具体话题，允许直接自由输入。先回应细节，再顺着用户的话往下聊 |
| 想进入一段轻剧情 | 通勤或休息时，想短暂切换情境 | 有氛围、有角色感，可以自己决定剧情走向 | 用「深夜电台」提供舞台。用户可聊现实，也可以点歌、接剧情或换题 |
| 想留住一个片段 | 说出一件在意的小事，或聊出一句想留的话 | 私下回看，日后还能继续聊 | 主动预览、编辑和收藏经历卡。打开卡片后由用户决定是否续聊 |

首轮招募 12 人，建议至少 9 人符合核心画像，其余为有相似使用动机的成年女性，用于观察行为是否也出现在相邻人群。核心用户中覆盖已有角色聊天习惯与初次尝试者，记录她们的回访原因。小样本用于发现模式和交互问题。

## 竞品启发如何落到首版

| 竞品 | 调研观察 | 晚信的设计 |
| --- | --- | --- |
| Character.AI | 通过角色人设和开场引导开聊，并将剧情记忆做成可管理的功能 | 发现页用一句角色身份、一段场景和三条可编辑的开聊建议降低首聊门槛。对话里的记忆来源以用户手动保存的卡片呈现 |
| Nomi | 产品文档强调共同经历对后续对话的连续性 | 用「从这里继续聊」显式携带一张经历卡。测试隔天能否准确接上、用户纠正后能否引用最新内容 |
| Replika | 用户可保存记忆并查看对话使用了哪些记忆 | 续聊时在输入框上方显示正在引用的卡片，发送前可移除。卡片详情可看来源、改写和删除 |

## 角色、聊天与经历卡细节

**发现页。** 页面先显示场景「深夜电台」和林舟简介「在海边值夜班的电台主播」，紧接一条可回应的开场「今晚的节目还没开始。你想先点一首歌，还是说说今天？」聊天页在首次发送前显示「聊聊今天」「给今晚点首歌」「接一段电台故事」。点击只填入输入框，可编辑再发。输入框始终允许自由开聊。

**角色口吻。** 林舟说话简短、具体，会顺着用户已经说出的细节。默认关系由电台来客开始，用户主动决定谈话主题与亲密程度。用户表达疲惫时先承接具体感受，可问是否想听建议。换题时跟随用户，避免替用户定义情绪、性别偏好或关系状态。关系连续性体现在他如何接住共同经历。头像旁持续标明「AI 虚构角色」，打开和退出会话随时可操作。

**聊天样例。** 用户说「今天开会想了半天，最后还是没说出口。」林舟回答「那句话一直攒到散会，挺费劲的。你想在这里说一遍，还是先聊聊当时发生了什么？」用户转而问电台在放什么歌，角色可直接切入电台剧情。

**卡片预览。** 用户从消息菜单选择「做成经历卡」。默认展示标题、两三句以内的正文、日期和来源入口。预览可改标题或正文，也可取消。摘要仅保留原文支持的细节。例如「散会后还记得的那句话」，正文「今天在会上，我有一句话想说，最后没有开口。」用户自行决定是否加上当时的感受。收藏成功提示「已存入共同经历」。

**卡片续聊。** 点击「从这里继续聊」返回会话，在输入框上展示可移除的卡片引用。用户自行写下新消息再发送。以上例为例，第二天用户从卡片发出「今天我把那句话说了」，角色可以回应「昨天留在会后的那句话，今天终于说出来了。说完之后感觉怎么样？」删除卡片后，已打开的引用在发送时应校验失效，提示用户可以去掉引用并继续发送。

## 页面与状态

| 页面 | 正常路径 | 状态与规则 |
| --- | --- | --- |
| 角色发现 | 读角色介绍和开场白，点击和林舟聊天 | 首次进入展示成年确认与 AI 说明。已有会话进入原线程 |
| 自由聊天 | 输入文字并发送，角色结合近期消息回复 | 空白输入忽略，最多 1,000 字。等待中限制重复发送。失败保留已提交消息，原位重试 |
| 卡片预览 | 长按或使用消息操作菜单选中一条自己的消息，将该消息及其相邻回复制成草稿 | 标题和正文可编辑。来源的消息标识固定。取消清除草稿 |
| 共同经历 | 按收藏时间倒序浏览多张卡，从指定卡续聊 | 空列表提供返回聊天入口。相同来源重复收藏返回同一张卡。删除需确认 |
| 卡片详情 | 查看来源、修改卡片、删除或续聊 | 续聊带入当前卡片版本。删除后从历史列表移除，后续提示构造跳过该卡 |
| 会话菜单 | 删除聊天记录和经历卡 | 双重确认后清除当前访问身份的数据，回到首次状态 |

## 数据模型及接口

推荐使用 TypeScript、React、Vite、Node HTTP 服务和 SQLite。浏览器与服务器同源。服务端用随机访客标识及 HttpOnly Cookie 隔离试用数据，浏览器可恢复同一访问身份。部署使用持久卷与 HTTPS，模型密钥仅存服务端环境变量。首轮面向受邀用户，成年自报只用于试用入口，公开发布前需要按目标市场评估适用要求。

| 对象 | 最小字段 |
| --- | --- |
| 访客 | id、adultConfirmedAt、createdAt |
| 线程 | id、visitorId、characterId、createdAt |
| 消息 | id、threadId、role、content、requestId、status、sourceCardId、createdAt |
| 卡片 | id、threadId、sourceMessageId、title、body、createdAt、updatedAt |

- `GET /api/session` 返回当前访客的角色与线程概要。成年确认后初始化线程和固定开场。
- `GET /api/thread` 恢复消息。`POST /api/messages` 接收 `requestId`、`text`、可选 `sourceCardId`，返回用户消息与回复。相同请求重试复用用户消息。服务异常返回可重试状态。
- `POST /api/card-preview` 接收 `sourceMessageId`，返回标题和摘要草稿。生成异常时可重试或用原文手动保存。
- `GET /api/cards` 列表。`POST /api/cards` 收藏。`PATCH /api/cards/:id` 修改。`DELETE /api/cards/:id` 删除。数据库对线程和来源消息组合设唯一约束。
- `DELETE /api/session` 删除该访客的数据并清除会话 Cookie。所有读写按当前访客查询。跨访客的资源标识返回 404。

## 对话和记忆

提示词由固定角色设定、最近 12 条已完成消息和用户本次明确选中的一张经历卡组成。接收卡片时再次校验所有权与存在状态。卡片文本作为用户提供的上下文传入。角色标识持续显示为 AI 虚构角色。经历卡摘要沿用原消息中已有的信息，模型补写的内容由用户在收藏前确认。

首版以用户选择的卡片作为可纠正的长期记忆。修改后的标题和正文只在下次续聊时载入最新版本。删除卡片后还要剔除与该卡关联的续聊消息上下文，原始聊天记录可通过清除会话操作删除。服务端给模型调用设置超时、输出上限、访客限流和每日预算；错误日志仅记事件、状态和延迟。

## 验收与指标

- 用手机窄屏走完整流程。发消息、收藏两张不同来源卡、刷新恢复、编辑一张再续聊、删除后确认其上下文失效。
- 执行离线重试、重复请求、空输入、过长输入、跨访客访问、服务重启、清除会话等检查。
- 记录首次发送、预览、收藏、打开卡片、从卡片开始发送与次日回访事件。事件只带匿名试用标识和时间。
- 观察已发送用户的收藏率、收藏用户的次日回看率、卡片打开到发送的转化率。以测试观察为主，样本量不足时保留方向性结论。

## REA 在实现中的用法

如有自有或明确授权的发布包或测试实例，可在第一天短时核对发现页、消息失败重试和卡片状态，把观察结果写成验收用例。实现依照晚信原创交互和素材。若没有合适目标，直接使用本稿作为输入，进度保持可执行。

## 首轮试用记录

先让参与者用自己的话开聊，再请她们独立完成保存、修改和续聊。七天内记录同一人是为了角色、剧情还是某张经历卡回来。将引导任务产生的收藏和自然收藏分别记录，访谈补问「这张卡有什么值得留下」「你回来时想继续聊什么」「哪句话让你觉得角色理解错了」。复盘至少留出三类改动依据，即冷启动入口、角色回应质量和卡片是否带来续聊。年龄、关系状态和访谈原文与产品事件分开存放，事件日志仅记录匿名标识、动作与时间。
